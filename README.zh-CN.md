# AI 行为见证与对账层

[English →](./README.md) · **中文**

> **你的 AI 什么都能做。但你能证明它做过什么吗？**

一个开源、可独立验证的 AI 调用与科研优先权证据层。

**在线演示：** [ai-attestation.com](https://ai-attestation.com) · **协议：** MIT

## 钩子

**2026 年 7 月**，马斯克承认：他的 AI 公司在未经用户同意的情况下，上传了客户的私有代码。

**如果他不认错呢？**

**2026 年 9 月**，Tristan Buckmaster 与 Levent Alpöge 私下研究 NS 方程爆破解近一年，把未发表草稿上传到 OpenAI Codex 辅助演算。随后 OpenAI 动用大规模 AI Agent，走同一条冷门路线抢下证明。

争议的核心不是「谁更会做数学」，而是：

- 我什么时候已经有这个想法？**没有证据。**
- 我和哪家 AI、说了什么？**厂商自己说了算。**
- 我有没有同意拿去训练？**口头回忆。**
- 期刊 / 机构怎么验？**只能看截图。**

**今天，AI 公司的行为完全依赖自我承诺。** 它们可以访问你的数据、调用你的 API、做出影响你业务的决策——但没有任何独立第三方能审计它们做了什么。

我们做了这个东西。我们在 2026 年 9 月上线了第一个公开版本。

---

## 我们做了什么

**一个不依赖任何 AI 厂商的第三方见证层。**

| 能力 | 说明 |
|---|---|
| **API 调用见证** | 把 SDK 的 `base_url` 指到我们的代理，每次调用自动写入 SHA-256 哈希链，**不存原文** |
| **科研优先权存证** | 把草稿发给任何 AI 之前，先在浏览器本地算指纹，再写入证据链 |
| **离线验证包** | 一键导出 ZIP（含 `verify.html`）。**断网、换电脑、不依赖我们的服务器**，都能独立验证 |
| **公开验证链接** | 生成一个 URL，甲方点开就能看链是否完整，无需登录、无需下载 |
| **合规即代码** | EU AI Act、中国《生成式人工智能服务管理暂行办法》等合规模板开源，可版本化、可自动执行 |

一句话：客户买的不是「我们更懂 AI」，而是 **出事时能对账、能重放、能给第三方验的决策保险**。

## 为什么开源

因为**「见证」这件事必须开源才有意义**。

闭源审计工具无法证明自己没有改数据。只有代码、算法、验证方法都公开，第三方才能真正独立复核。

合规模板和验证方法采用 MIT。托管版是开箱即用的路径；如果你不信任我们，也可以自己 fork、自己部署、自己验证。

## 诚实边界

**这个工具能支撑的：**

- 在某个时间点，某份内容（通过哈希）确实存在
- 某次 API 调用发生了，请求 / 响应哈希在链上未被改写
- 哈希链完整，未被篡改

**这个工具不能证明的：**

- 某家 AI 厂商训练或阅读了你的内容
- 你的论文一定先于他人完成
- 替代律师函、公证处或合格 TSA（可信时间戳服务）
- 法院必然采信

我们宁可把边界说清楚，也不想让你在关键时刻才发现工具做不到。

## 快速开始

### 托管版（最快）

1. 打开 [ai-attestation.com](https://ai-attestation.com) → 左侧 **Key 管理** → 创建 → 复制 `ata_xxxxxx`。
2. 把 AI 调用指到代理：

```python
from openai import OpenAI

client = OpenAI(
    base_url="https://ai-attestation.com/v1/proxy",
    api_key="sk-your-upstream-key",  # 你的 DeepSeek / OpenAI / Anthropic Key
    default_headers={
        "X-Attest-Key": "ata_your_key",
    },
)

resp = client.chat.completions.create(
    model="deepseek-chat",
    messages=[{"role": "user", "content": "hello"}],
)
```

3. 回到网站 → **API 调用记录** → 点开一条 → 看哈希链。
4. 调用详情 → **导出验证包** → 解压 → 打开 `verify.html`。
   不需要联网，不需要登录，不需要信任我们。

没有上游 Key 时，可在仪表盘点 **模拟一条调用**（`POST /v1/demo/simulate`）。

### 自己部署

```bash
# 后端 — http://127.0.0.1:8004
cd backend/app
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
uvicorn main:app --host 127.0.0.1 --port 8004

# 仪表盘 — http://127.0.0.1:3002
cd frontend
npm install && npm run dev
```

本地代理：`http://127.0.0.1:8004/v1/proxy`，请求头 `X-Attest-Key`。
可选环境变量：`ATA_HOME`、`ATA_SMTP_*`、`ATA_DASHBOARD_URL`、`ATA_UPSTREAM_*`。详见源码与 [`SECURITY.md`](./SECURITY.md)。**不要把未加固的 MVP 直接暴露公网。**

```bash
cd backend && PYTHONPATH=app python -m pytest tests/ -q
```

## 与开放数学模型计划（SAIR）的关系

2026 年 9 月，陶哲轩与多位菲尔兹奖得主发起 SAIR 基金会的"开放数学模型计划"，明确提出三条原则：

- 未经研究者明确同意，数据不应进入训练集
- 模型成果需要可追溯来源
- 输出结果需要可重复、可检查的验证过程

AI 行为见证层为三条原则都提供了技术落地工具：

- **明确同意**：按厂商记录训练数据同意，每次变更写入证据链
- **可追溯来源**：科研优先权存证 + 调用到工件的时间线
- **可重复检查**：离线验证包 + 公开验证链接

我们不隶属于 SAIR，也不替代它的治理框架——我们提供的是"可核验证据"这一层。

## 常见问题

**和 LLMOps 工具有什么区别？**
LLMOps 帮开发者调试、监控自己的应用。我们做的是独立于厂商的第三方见证——不依赖 OpenAI、Anthropic 或任何厂商控制台，哈希链可被任何第三方离线复核。简单说：LLMOps 是给自己看的，我们是给客户 / 监管 / 甲方看的。

**数据安全怎么保证？会不会把正文传给你们？**
不会。API 调用见证只保存哈希，请求和响应正文不落库。科研存证更彻底：在浏览器本地算哈希，原文不上传，服务器只收到 64 位指纹。

**客户拿到验证包，真的能独立验证吗？**
能。ZIP 里有 `verify.html`，断网、换电脑、不依赖我们的服务器也能重算哈希链。公开验证链接则连下载都不需要。

**这个东西有法律效力吗？**
我们提供的是技术证据和时间线，不是法律意见，也不替代公证处。能力边界见上方 **诚实边界**。

**你们能证明 OpenAI 训练了我们的数据吗？**
**不能，我们也不会这么说。** 我们能证明的是：你在某个时间点确实拥有某份内容（指纹 + 时间戳），以及你与某家厂商发生过某次调用（哈希链）。厂商是否拿去训练，只能由厂商自己的审计日志和法律程序回答。

**开源的话，我们自己 fork 不就行了？**
可以。合规模板和验证方法都是 MIT。托管版提供的是开箱即用：不用自己养服务器、不用自己做验证页、不用处理公开链接。自己试试用开源版；要给客户「一个链接就能验」，托管版更快。

**怎么收费？**
开源版免费，托管版按试用 / 订阅。目前处于试点阶段。

## 技术架构

```text
你的 SDK
   │
   ▼
/v1/proxy  ──► 转发上游（OpenAI / Anthropic / DeepSeek / Zhipu（智谱） / …）
   │
   ├─ 只算哈希，不存原文
   ├─ SHA-256 链：prev_hash → chain_hash
   └─ 写入统一证据链
         │
         ▼
    仪表盘 · 合规检查 · 离线验证包 · 公开验证链接
```

- 后端：FastAPI + SQLite
- 前端：Next.js 14
- 密码学：SHA-256 哈希链、本地时间戳；可选 OpenTimestamps / 链上锚定
- 开源协议：MIT
